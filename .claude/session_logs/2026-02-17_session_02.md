## Key Decisions Made

### Decision 1: Use GitHub CLI for Git Authentication
**Problem**: macOS keychain (`git-credential-osxkeychain`) was blocking Git pushes — password not accepted
**Solution**: `gh auth login` (browser-based) + `gh auth setup-git` to route credentials through GitHub CLI
**Rationale**: Bypasses keychain entirely, persistent fix, no password required going forward

### Decision 2: Claude.ai vs Claude Code — Complementary Tools
**Decision**: Use Claude.ai (browser) for planning, decisions, and reviews; Claude Code (terminal) for file creation, Git, and code
**Rationale**: Browser Claude is the "planning meeting", Claude Code is "working in the project"

### Decision 3: Prototype Sprint Before Milestone 1
**Context**: JSON data format and architecture need to be locked down before coding — but interaction types were still abstract
**Decision**: Build 6 standalone prototype scenes first to discover what feels right on a touchscreen
**Rationale**: Better to design the data format around interactions you've actually built and played with, not ones you imagined. Like doing motion tests in After Effects before committing to a full animation.

## Problems Solved

### macOS Keychain Issue
**Symptom**: `git-credential-osxkeychain wants to access "Docker Credentials"` — password not accepted
**Root Cause**: Keychain login password out of sync; Docker credentials stored in keychain conflicting with Git
**Fix**:
```bash
gh auth login        # authenticate via browser
gh auth setup-git    # route git credentials through gh CLI
```
**Status**: ✅ Resolved — pushes now work without keychain prompt

## Prototype Sprint Plan

**Goal**: Discover what interactions feel right before locking down architecture or data format.
**Rules**: Each prototype is fully self-contained — one Godot scene, no shared code, no architecture. Feel over structure.
**Location**: `/prototypes` folder in the repo
**Build order**: Simple → complex

| # | Scene | Core Interaction | Input Type |
|---|-------|-----------------|------------|
| 1 | Suitcase packing | Drag items into correct target zones | Drag & drop |
| 2 | Cleaning room | Tap clutter objects to make them disappear | Tap |
| 3 | Bring into focus | One or more sliders reveal a sharp image | Slider |
| 4 | Memory game | Tap pairs of matching objects; mismatch cancels selection | Sequential tap + match logic |
| 5 | Polaroid map | Shake polaroids to reveal photos on a travel map | Shake/swipe + reveal animation |
| 6 | Painting reveal | Brush/swipe across canvas to progressively reveal image | Continuous swipe stroke |

**Each prototype has**:
- A rough story context (not placeholder shapes)
- A simple success state — input → response → feedback
